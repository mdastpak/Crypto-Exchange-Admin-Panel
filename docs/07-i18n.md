# 07 - Localisation

Only Persian (`fa`, RTL) is shipped now. The structure for more languages exists from the first commit.

## Rules

1. **No hard-coded UI text.** Every visible string uses `t('namespace.key')`. A lint rule (`i18next/no-literal-string`) fails the build otherwise.
2. **One namespace per feature** (`currencies`, `withdrawals`, ...), plus `common` and `errors`. Files live in `src/i18n/locales/<lng>/<ns>.json`.
3. **Backend error codes map to messages.** The panel translates by `code` (`errors.version_conflict`), not by the backend `message`, and falls back to the backend message for unknown codes.
4. **Direction from the locale.** `<html lang dir>` is set from the active locale; the backend `GET /public/locales` is the source of `dir` when available. Layout uses CSS logical properties (`margin-inline-start`, `ps-*`, `text-start`), never `left`/`right`.
5. **Numbers, dates, and currency amounts go through `lib/format`.** Amounts stay decimal strings and are formatted by locale without losing precision. Persian digits are for display only; inputs accept Persian, Arabic-Indic, and Latin digits and normalise them to Latin before sending.
6. **Calendar.** Dates are stored and sent in UTC. The display calendar (Jalali or Gregorian) is a user setting; the default for `fa` is Jalali, with the Gregorian date available on hover. Timestamps always show a time zone.
7. **Mixed-direction text.** Addresses, hashes, symbols, and amounts are wrapped in `<bdi>` (or Unicode isolates) so `BTC/USDT` and `0x...` keep their direction inside Persian text.
8. **Icons that imply direction** (arrows, chevrons) flip in RTL.
9. **Pluralisation and parameters** use ICU message format through i18next.
10. **Fonts.** Vazirmatn (bundled, no CDN) for Persian; a system sans for Latin.

## Adding a language later

1. Add `src/i18n/locales/<lng>/` with every namespace.
2. Add the language to `SUPPORTED_LOCALES` with its direction.
3. Enable the switcher in the header (hidden while only one locale exists).
4. Send `X-Locale` on every request (already done), so backend messages follow.

No component changes are needed if the rules above were followed. A CI check compares keys across locales and fails on a missing key.
